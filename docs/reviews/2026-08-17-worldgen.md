# World Generation Review — dwarf.land

**Scope:** `public/index.html` world-gen pipeline (`LAND`, `CITIES`, `noise`/`prand`, `isLandAt`, `getBiome`, `generateMap`, `biomeStartRes`, road gen). Reviewed statically **and dynamically** — the exact pipeline was extracted unmodified into a Node harness and executed, so every number below is measured, not estimated. Rendered output map attached (`worldmap.png`).

**Verdict:** the approach (hand-authored continent ellipses + noise-perturbed coasts + regional biome overrides) is smart, legible, and very cheap to author — right call for an emoji-scale planet. The issues are: a heavy synchronous startup, silent city loss, non-determinism vs. the delta-only save model, oversized beaches, a few biome realism gaps, and a fragmented road graph. All fixable without changing the architecture.

---

## P0 — Correctness / player-facing

### 1. `generateMap()` blocks the main thread for ~20s
Measured **19.8s** in Node on a desktop-class VM (browser will be similar order; mobile worse). It runs synchronously in `init()` (`index.html:6639`) before first paint — the tab looks dead on load.

Root cause: per-tile `isLandAt()` loops over ~110 ellipses, and each land tile calls it **5×** (1 land check + 4 `nearOcean` probes) → roughly **1.1B ellipse tests**.

Fixes (any one helps; together they're ~100×):
- Rasterize the ~110 ellipses once into a `Uint8Array` land bitmap (O(total ellipse area), microseconds), then world gen is pure array lookups. The noise-perturbed lookup (`lon + cn`) works unchanged against the bitmap.
- Yield per N rows (`await new Promise(r => setTimeout(r))`) so the page stays alive, or move gen into the existing Web Worker.
- Persist the generated base map (RLE-compresses extremely well at ~40 tile types) in the save; regenerate only on version change.

### 2. 9 of 125 advertised cities are silently dropped
Measured: **116/125 placed**. Dropped: `cape-town, manila, jakarta, miami, kingston, quito, accra, dakar, antananarivo`.

Cause: the `LAND` ellipses don't cover their real coordinates, and the nudge search (`index.html:1638`) only reaches ±10 tiles. Examples: the Florida ellipse `[-88,23,6,5]` ends at lon −82 but Miami sits at −80; there are no ellipses at all for the Philippines, Java, the Cape peninsula, Ecuador, the Ghana/Senegal coast, or Jamaica. `if (!placed) continue;` (`:1649`) fails silently.

Fixes: add/adjust ellipses (or nudge city lon/lat to match the drawn landmass); `console.warn` on any drop; extend `tests/city-placement.test.ts` to assert **all 125** place. 26 more cities get nudged up to 19 tiles (Sydney 18, Damascus 19, Rabat 18) — those placements work but the city no longer sits at its real location; fine at this abstraction, worth knowing.

### 3. The world is non-deterministic, but saves only store deltas
Measured: two runs of `generateMap()` differ on **45,478 tiles (2.27%)** — mushrooms, resource overlay, and biome-transition scatter all use unseeded `Math.random()`. On load, `restoreState()` re-runs `generateMap()` and replays `saved.mapDeltas` on top (`:6385`), so every session the base world quietly reshuffles: the iron deposit a player mined last session may not exist; new mushrooms appear under cities.

Fix: seeded PRNG (`mulberry32(worldSeed)`) for every `Math.random()` inside generation; store `worldSeed` in the save (slots into the `SAVE_VERSION` work already queued as P2 in `TODOS.md`). Bonus: makes P0-1's "persist base map" option optional.

## P1 — Geography / systems quality

### 4. Beaches average 6 tiles deep (should be ~1–2)
`nearOcean` (`:1502`) probes ±2° ≈ **±11 tiles**, so "beach" is a coastal belt, not a shoreline. Measured: 42,538 beach tiles, mean distance-to-ocean **6.0**, max 17, **62%** of beach tiles are ≥5 tiles inland. The attached map shows the thick tan halo around every continent. Fix: probe ±0.2–0.4° (1–2 tiles) or compute distance-to-ocean ≤2 from the land bitmap.

### 5. Biome realism gaps
- **Australia renders as a mountain range** (visible on the map: a grey blob). The global altitude noise (`alt > 0.55 → MOUNTAIN`, `> 0.35 → HILL`) runs *before* regional overrides and has no mask; there is no Australian-outback desert override. Result: `DESERT` = 1.14% of world tiles while `TUNDRA` = 7.76%.
- **Central Brazil gets a Sahara-sized desert** from the generic 20–35° band rule (`:1483`). The Atacama/Andes region has no override at all; neither do the Himalayas/Tibet, while the US Midwest gets random mountain blobs.
- Fixes: add regional overrides for Australia (desert interior), Andes, Himalayas (mirror the existing Rockies pattern); consider gating the global `alt` mountains to those ranges so plains stay flat.

### 6. Road network is fragmented into 95 groups (largest = 5 cities)
Each city links only its 2 nearest (`:1837`), A* is land-only. Measured: **137 road components**, 95 city groups, largest chain `istanbul–krakow–vienna–prague–kyiv` (5). Europe isn't one network; North America is shards. Only 6,746 PATH tiles total. Fine if roads are meant as local flavor; a problem for trains/cars/intercity trade at continent scale. Fix if desired: per-landmass MST over cities (guaranteed full connectivity at similar total length), +1–2 extra edges for loops.

### 7. `buildRoad` cost bugs (`:1782`)
- `T.PATH` is missing from `TERRAIN_PROPS` → falls to the default cost **5** (same as mountains). New roads *avoid* existing dirt paths instead of merging into corridors. Add `[T.PATH]: { speed: 1, … }` and a `tc ≈ 0.5` preference in `buildRoad`.
- Heuristic is Manhattan **tile count** but min per-step cost is 0.1–0.5 → inadmissible heuristic, A* degenerates to greedy and returns suboptimal roads within the 15k step cap. Scale h by ~0.5.
- `T.FLOOR` isn't in the no-overwrite list → roads pave through city plazas (cosmetic).

## P2 — Polish

8. **Scatter-pass bias** (`:1529`): the neighbor list is fixed-order `[N,S,W,E,…]` with a `break` on first difference → northern tiles bleed preferentially; in-place mutation smears along scan direction. Pick a random differing neighbor and double-buffer each pass.
9. **Single-octave value noise** over a `sin()` hash → blobby, low-detail features (visible as smooth grey blobs). 2–3 octaves of fBm is a few lines and much more organic.
10. **`biomeStartRes` duplicates biome logic by lon/lat** (`:981`) and can disagree with the actual generated terrain under the city (a city in generic-band desert gets temperate resources). Cheaper to keep truthful: sample the generated tiles around `city.mx/my` after placement and derive starting resources from those.
11. **Stale splash copy** (`:424`): still says "500×250 tile planet … 29 real-world cities" — actual is 2000×1000, 125 cities (116 placed; see P0-2).
12. **Pole wrap inconsistency**: `isWalkable` uses `wrapY` (walking off the north edge teleports to Antarctica) while `bfs`/`terrainCost` treat `y<0` as blocked. Pick one; the map is advertised as wrapping horizontally only.
13. **Threshold drift**: city placement requires `countLandTiles ≥ 6` but the coastal nudge accepts `≥ 5` — harmless, but looks accidental.

## Suggested order of attack
1. Seeded RNG (P0-3) — smallest diff, unblocks testing of everything else.
2. City drops + loud failure + placement test (P0-2).
3. Land-bitmap rasterization (P0-1) — makes gen ~instant; beach fix (P1-4) becomes trivial on the same bitmap.
4. Australia/Andes/Himalaya overrides (P1-5).
5. Road cost fixes (P1-7), then decide on MST (P1-6) as a design call.

*Method note: harness extracted the unmodified gen code from `index.html` and ran it in Node 22; map rendered from the same run. Numbers will vary slightly per run until the seed lands (P0-3).*
