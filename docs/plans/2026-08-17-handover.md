## W0 — Before anything else: persistence is probably already broken

Found by the 2026-08-17 review, verified three ways (two independent reviewers plus a direct
D1 query). This was not known when the day started.

```
SELECT length(state), datetime(updated_at,'unixepoch') FROM game_state WHERE id=1;
  -> 2,190,497 bytes
  -> 2026-07-26 20:08:36     (22 days before this plan was written)
```

Cloudflare documents a **2,000,000-byte** maximum row size for D1. The live row is 9.5% over
it, and no successful write has landed in three weeks. Either nobody has played since July 26,
or every autosave since then has failed. **Nobody can tell which, because the client never
checks the response.** The live write is the worker path at `public/index.html:6533-6539`
(`case 'save_response'`), where `fetch` is called **without `await`** inside a `try`, so its
`catch (_)` catches nothing and a rejection becomes an unhandled promise rejection. The
main-thread `saveGameState()` at `:5779-5790` is a dead branch in normal operation: it returns
early whenever `workerActive && gameWorker` (`:5780-5782`), and the worker is the default. A
fix applied only at `:5785` would change nothing. The `beforeunload` beacon at `:6377` sits on
that same dead path; the live path posts `save_request` to a worker being torn down
(`:6371-6374`), which is an independent data-loss channel unrelated to the size limit.

Do this first, before any other item:

1. Check whether writes are failing. Safe method: `npx wrangler tail` while loading the game,
   or write a scratch row (`id=999`, not `id=1`) sized like the real one and see if D1 accepts
   it. Do not test against `id=1`; that row is the world.
2. **Take a D1 export now**, before touching anything. If the world is intact, that export is
   the only copy. D1 Time Travel retains 7 days on Free, 30 on Paid, so it will not survive a
   year of dormancy on its own.
   **Done 2026-08-17:** `~/Backups/dwarf-land/d1-export-20260817.sql`, 6.3 MB, all 7 tables,
   27,305 inserts, including the world row (`INSERT INTO "game_state"`, tick 352983, year 45).
   Taken with `npx wrangler d1 export dwarf-planet-db --remote --output <path>`. It lives
   outside the repo and outside Cloudflare; if that machine goes, so does the backup. Copy it
   somewhere durable and record where under W5.
3. Only then size the payload. The save grows monotonically: `mapDeltas` holds one entry per
   tile ever modified, and per-dwarf `eventLog` is UI history rather than simulation state
   (written at `public/index.html:5753`, `public/game-worker.js:2598`, kept at `.slice(-50)`).
   The review measured `eventLog` at roughly 39% of the whole save. Trimming it, and packing
   `mapDeltas`, brings the payload back under the limit. Shrinking comes before capping.

## What "parking" means here

Not deletion. The site stays up, the code stays public, the tests stay green. Parking means:
nobody is on the hook, the repo does not rot into a state where returning is expensive, and
nothing left running can quietly cost money or lose data.

## Accepted risks

Recorded so a future reader knows these were chosen, not missed.

- **The OpenRouter key stays live** on a project nobody is watching. Accepted 2026-08-17 (D6).
  An earlier draft called this an "$8.50/hour ceiling". **It is not a ceiling.** `checkBudget`
  (`src/guardrails/budget.ts:29-41`) reads the spend total, decides, and only records usage
  after the model call returns, so concurrent requests all pass the same check; and
  `checkRateLimit` keeps its buckets in module scope (`src/guardrails/rate-limiter.ts:9-11`),
  which bounds one isolate rather than the account, so N colocations give N times the limit.
  The caps are a brake, not a wall.
  **Mitigation that actually holds, and is not in the code:** set a credit limit on the
  OpenRouter key at the provider. Provider-enforced, independent of this codebase, two minutes.
  For a dormant project this is the single highest-value item in this document.
- **Road scrapping is switched off in production right now.** All three call sites are
  commented out (`TODOS.md:10-15`), and the suite never caught the underlying bug because
  `tests/smart-roads.test.ts:61` mirrors `isOrphanRoad` instead of importing it. The site is
  being parked with a feature disabled behind a green test suite. Recorded so nobody later
  mistakes the green suite for full coverage.
- **Two public routes grow D1 without bound.** `/api/craft` inserts a `craft_items` row for
  any novel name before the cache check and before the budget check (`src/worker.ts:301-331`);
  `f81c42f` bounded row *length*, not row *count*. `/api/sponsor/checkout` creates a pending
  row per call with no rate limit (`TODOS.md:122-131`). Slow burn rather than same-day, which
  is exactly why it matters across a year of dormancy.
- **Sponsorship calls are not reserved atomically.** The worker selects rows with calls
  remaining, calls the paid model, then decrements (`src/worker.ts:172-182`), so concurrent
  requests can spend one entitlement more than once.
- **Polar sponsorships remain active.** Rows in `dwarf_sponsorships` still carry
  `calls_remaining`. If the project is ever forked to a different Polar account, those
  silently stop working. Accepted 2026-08-17 (D6); revisit before any transfer.

### P2 — Bound the live surfaces

- **W4. Cap the state-save payload — after W0's shrink, not before.** An earlier draft called
  this "roughly 20 lines" and "the best first task for anyone new." Both were wrong, and the
  review said so on every count. It is the change with the most hidden coupling in the repo.
  What it actually requires:
  - **Enforce on real bytes, not `Content-Length`.** `TODOS.md:114-115` says to reject on the
    header; the header is caller-supplied and a chunked body may omit it. Read
    `c.req.arrayBuffer()` and check `byteLength`, or count while draining the stream and abort
    past the cap. Workers accepts bodies far larger than a 128 MB isolate can hold, so an
    unbounded `c.req.json()` is itself the risk. Return `413`.
  - **Enforce again in `saveState`** (`src/db/state.ts:5`). `JSON.stringify(state)` is the
    string that actually meets D1's limit, and it can differ from the request body. Checking
    only the route leaves the database constraint unguarded. That file has **zero** tests today.
  - **Ship the client change in the same commit, at `public/index.html:6534`** (the worker
    `save_response` path), mirroring it at `:5785` for the fallback branch. Without it, a 413
    is silent and the 60s autosave loop keeps firing into the void. This is the difference
    between W4 fixing a theoretical abuse path and W4 causing a guaranteed data-loss bug.
  - **Tests:** over-cap → 413 with the stored state unchanged; at cap−1 → 200; **understated
    `Content-Length` over cap → still 413** (the only test that distinguishes a correct fix
    from the one `TODOS.md` describes); chunked body with no `Content-Length` → 413. The
    harness already exists in `tests/worker-routes.test.ts` (`MockDB` + `app.request()`).
  - **A size cap is not an authorization boundary.** `isAllowedOrigin` (`src/worker.ts:34-38`)
    compares `Origin` against the request's own origin; one curl flag defeats it, and
    `STATE_WRITE_TOKEN` is only required when it is set, so unset-in-production is the weaker
    configuration. Capping size does not stop anyone writing a valid-shaped garbage world.
    Treat the W0 export as the real safety net.
- **W5. Record the operational facts — do this first, it is 15 minutes.** It is the only item
  in this document that cannot be reconstructed from the repo, and it is mostly already
  discoverable: the owning Cloudflare account and account id from `wrangler whoami`, the D1
  id at `wrangler.jsonc:10`, every secret name in `.dev.vars.example`. Add what those cannot
  tell you: where DNS for dwarf.land lives, which account is billed, who administers the
  GitHub repo, where the W0 export is kept, and how to roll back a bad deploy
  (`wrangler versions` / `wrangler rollback`). Also add a retention line for `ai_log`, which
  gains a row per AI call (`src/guardrails/budget.ts:74-76`) and has no cleanup.

### P2b — The two things that break a parked site with no deploy

Neither was in any earlier draft. Both are external drift, which is the failure mode dormancy
actually produces, as opposed to the server-side work the rest of this document describes.

- **W8. Pin `daub-ui`.** `public/index.html:8-9` loads the entire UI layer, CSS and JS, from
  `https://cdn.jsdelivr.net/npm/daub-ui@latest/`. A breaking major release or an unpublish
  takes down the live site with no commit, no deploy, and no alert. Five of the six `DAUB.*`
  call sites are unguarded (`:331, 408, 409, 464, 6643`); only `:6528` checks `typeof DAUB`.
  `src/worker.ts` loads the same `@latest` for the `/success` page. Pin an exact version, or
  vendor the two files into `public/`. Ten minutes, and it is the highest-value external fix.
- **W9. Give the dormancy checkpoint a mechanism.** `.github/workflows/ci.yml` triggers on
  push and pull request only, so a parked repo runs CI zero times and the suite rots against
  upstream drift undetected. Add a monthly `schedule:` cron. Have that job also fail when the
  newest commit is older than 90 days, which turns success criterion 6 from an intention into
  a red email. A checkpoint that depends on someone remembering is the exact failure this
  document exists to prevent.

### P3 — Housekeeping

- **W6a. Fix or delete the README's craft-seeding section.** `README.md:188-194` tells the
  reader to run `npx tsx scripts/import-craft-data.ts`. `tsx` is in no dependency list, the
  download is ~98 MB, and the script writes `migrations/0003_craft_seed.sql`
  (`scripts/import-craft-data.ts:19`) which collides with the existing `0003_crafting.sql`.
  Duplicate prefixes fail `tests/migrations.test.ts`. Following the README turns a green suite
  red. Renumber the output to `0006_`, add `tsx` to devDependencies, or delete the section.
  Related: `README.md:60` presents the 296 seeded items as shipped; no migration contains a
  single `INSERT INTO craft_items`, so a fresh clone starts empty and, with no API key, caches
  local-fallback junk names into D1 permanently.
- **W6b. Say that the game runs with no keys at all.** `README.md:157-162` reads as though
  `.dev.vars` is required. It is not: `npm install && npm run dev` gives a playable world. A
  returning reader otherwise burns ten minutes on an OpenRouter signup before seeing anything.
  While there: pin the Node version (CI uses 22; `package.json` has no `engines`, no `.nvmrc`)
  and change `npm install` to `npm ci`, since caret ranges on `wrangler`, `ai` and `hono` mean
  a year-later install is not the build these 453 tests passed against.
- **W6c. Note the silent-AI failure mode**, or fix it. With no `OPENROUTER_API_KEY` the router
  swallows all three model failures (`src/ai/router.ts:107-118`), the route answers HTTP 200
  with `model: 'local-fallback'` (`src/worker.ts:185-191`), the client checks only `resp.ok`,
  and `public/index.html:6603` logs "AI-powered decisions active" unconditionally at boot. The
  game reports that AI is on while running pure local logic and burning three failed HTTP
  round-trips per decision. Same shape for a missing local D1: the world silently resets on
  every refresh and the symptom never names its cause.
- **W6. Delete `PROGRESS.md`.** It claims Phase 2 in progress and `index.html` at ~1,300 lines
  against an actual 6,656, while the README documents those phases as shipped. Nothing in it
  is worth updating.
- **W7. Settle the licence.** `package.json` declares ISC; no `LICENSE` file exists. Owner's
  decision, and a public archived repo should be unambiguous about it.

### Optional — the `public/sim/` extraction (D5)

Approved 2026-07-25, unbuilt, and it stays that way unless someone chooses it.

The problem it solves is real: 79 function names are defined in both `public/index.html` and
`public/game-worker.js`, and the simulation exists a third time inside hand-copied tests.

**Correction to an earlier draft of this document**, which claimed none of the 453 tests
execute real code. That is false and a returning reader would catch it in two minutes. Roughly
94 do: `tests/road-repair.test.ts:67`, `tests/travel-modes.test.ts:86` and
`tests/economy-industry.test.ts:19` load `public/game-worker.js` under `node:vm`, and
`tests/worker-routes.test.ts` plus `tests/input-validation.test.ts` drive the real
`src/worker.ts`. The accurate and narrower claim: **`public/index.html`'s copy of the
simulation is executed by nothing**, and `tests/game-logic.test.ts` and
`tests/city-placement.test.ts` re-implement it by hand. That still argues for the extraction.

The cost lands on exactly one activity: changing a simulation rule. Five months of commits
shipped fixes *through* the duplication without paying it.

So the honest framing is conditional. **If you intend to change simulation rules, do the
extraction first. If you are here to fix a bug or read the code, ignore it entirely.**

If taken up:
- Read `docs/plans/2026-07-25-sim-extraction.md` (after W1) in full. It is good and it is
  detailed. Steps 1 and T6 are already done (`98fdfd4` landed the worker lifecycle fix).
- **Correction to that document and to this one's earlier draft:** `index.html` contains
  **zero** `window.*` assignments, not 11 and not 5. The five greppable matches are
  `window.addEventListener` at lines 3680, 5204, 5205, 5454 and 6371. The actual rescoping
  hazard is roughly 168 top-level function declarations plus `G` in a classic inline script;
  `type="module"` rescopes all of it at once. Re-measure before trusting any count in either
  document.
- **Kill condition.** If the differential parity gate (its step 7) has not passed within two
  weeks of starting, stop and write down what diverged. A stalled parity gate means the plan
  or an undocumented invariant is wrong, not that the person is. Do not push through it.

## Success criteria

Testable, and none of them assume a second person exists.

1. A fresh clone contains everything needed to understand the project: `CLAUDE.md`, both plan
   documents, no citation pointing outside the repo. Verify with
   `grep -rln "gstack/projects" TODOS.md README.md CLAUDE.md` returning nothing. (Scope the
   grep to those files. A repo-wide search matches this document quoting its own pattern.)
2. `CLAUDE.md` states no fact contradicted by the code. Specifically it does not repeat the
   500x250 / 28-cities figures.
3. `POST /api/state/save` rejects an oversized body, with a test covering it.
4. The operational facts in W5 exist in writing somewhere a future reader will find.
5. `npm test` green, CI green, dwarf.land serving.
6. **Dormancy checkpoint, automated:** the monthly CI cron from W9 fails when the newest commit
   is older than 90 days. That red email is the trigger to revisit the accepted risks above.
   Verify by checking the workflow has a `schedule:` block, not by intending to remember.
7. `curl -s https://dwarf.land/api/health | jq .ok` returns `true`. Criterion 5 previously said
   "dwarf.land serving" with no command attached to it.
